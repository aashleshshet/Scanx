New to API security?

An API is how applications exchange data. Scanx checks how an API handles access and suspicious requests, then explains what needs attention.

Start with the sample: no installation, account tokens, or API access is needed.

Read the beginner’s walkthrough →

01

Start with evidence

Explore a synthetic vulnerable or protected API, or import a JSON report produced by the Scanx CLI. No API is contacted in the hosted report explorer.

02

Run the web scanner

Install the Python server on your machine. Enable each API root you intend to scan, then open the local dashboard.

pip install -e '.[web]'
scanx-web --target https://your-api.example/v1

Open http://127.0.0.1:8765 in your browser.

03

Configure your assessment

Upload an OpenAPI/Swagger specification and a scenario file with known private objects. Provide two user tokens to test authorization across identities.

OpenAPI example ↓Scenario example ↓
04

Read results with context

Severity describes impact. Confidence describes evidence strength. A passed check covers a specific experiment; skipped and inconclusive checks identify coverage gaps.

Your scanner. Your environment.

Live scans run through Scanx’s Python server. Start it locally with an allowed API target, then use this same dashboard to configure and run your assessment.

pip install -e '.[web]'
scanx-web --target https://your-api.example/v1

Then visit http://127.0.0.1:8765. The hosted edition supports sample assessments and JSON report imports.

Choose your specification to discover authentication schemes.

Tokens are used for this scan only and excluded from reports. Scenario environment variable names are not read by the web server.
